# MiOpIIk 0.2 transition plan

> Status: implemented for the 0.2.0 release candidate. This document records the compatibility boundary from 0.1.x into 0.2. No published npm package is unpublished; compatibility and opt-in package names remain resolvable.

## Goals

MiOpIIk should keep owning workflow policy that is specific to MiOpIIk, while delegating generic runtime mechanics to DeepSeek Harness whenever DSH already provides a stable native capability.

0.2.0 reduces the default mounted runtime from nine historical plugin rows to five (`tool-recovery`, `executor`, `model-auth`, `diagnostics`, `recall`) while converging long-term ownership on three domains: recovery, policy and diagnostics. Existing 0.1.x package names remain installable through compatibility/opt-in surfaces.

## Compatibility promises

- Existing 0.1.x packages remain published. Do not unpublish them.
- 0.1.x stays maintenance-only: security fixes, upstream compatibility, correctness bugs and documentation. No new feature package is added.
- A package is removed from the default meta bundle only in a 0.2 minor release.
- Existing tool names stay stable through the 0.1.x line.
- Any 0.2 replacement must ship a migration note before the old implementation is retired.
- Published legacy packages may remain as compatibility shims for at least one 0.2 release before npm-level deprecation is considered.

## Target domains

| 0.2 domain | Responsibilities | Current packages feeding it |
|---|---|---|
| recovery | manual checkpoints, event-driven checkpoints, rewind, prune, recovery rules | `dsh-miopiik-tool-recovery`, `dsh-miopiik-checkpoint` |
| policy | explicit model/provider authorization, fail-closed routing and delegation policy | `dsh-miopiik-model-auth`; policy portions of `dsh-miopiik-executor` |
| diagnostics | capability/compatibility probe plus programmatic run/token telemetry | `dsh-miopiik-capabilities`, `dsh-miopiik-run-stats` |

`dsh-miopiik` remains the single recommended install entry and owns preset assembly plus migration compatibility.

## Package lifecycle

| Package | 0.1.x | 0.2 direction | Reason |
|---|---|---|---|
| `dsh-miopiik` | maintain | keep | one recommended install surface |
| `dsh-miopiik-tool-recovery` | maintain | core recovery package | checkpoint/rewind is still distinct MiOpIIk value |
| `dsh-miopiik-checkpoint` | maintain | merge into recovery | automatic and manual checkpoints are one recovery domain |
| `dsh-miopiik-model-auth` | maintain | evolve into policy | explicit authorization/fail-closed routing remains MiOpIIk-owned |
| `dsh-miopiik-capabilities` | maintain | merge into diagnostics | runtime compatibility probing belongs with telemetry |
| `dsh-miopiik-run-stats` | maintain | merge into diagnostics | DSH owns token projections; MiOpIIk only needs a thin programmatic view |
| `dsh-miopiik-executor` | bugfix only | native subagent policy adapter; later fold into policy domain | DSH owns the child runtime/lifecycle; MiOpIIk keeps explicit route, leaf, persona/tool-scope and result policy |
| `dsh-miopiik-recall` | bugfix only | compatibility shim, then leave default bundle | DSH now owns workspace/session search, trace and exact event read |
| `dsh-miopiik-learn` | bugfix only | leave default bundle; keep the learn workflow, not skill infrastructure | DSH now owns skill registry/filesystem/discovery |
| `dsh-miopiik-magic-keywords` | bugfix only | optional legacy plugin, not default | implicit notice injection is non-core and increases hidden control flow |

"Bugfix only" means no feature expansion unless required for security or an upstream breaking change.

## Native DSH replacement rules

### Executor

Do not grow a parallel executor runtime.

MiOpIIk should own the policy contract:

- route must be explicit where MiOpIIk requires explicit routing;
- unauthorized routes fail closed;
- executor is a leaf under the MiOpIIk depth budget;
- tool scope and task/acceptance contract remain explicit.

DSH should own the runtime mechanics: subagent start/continuation, persona delivery, toolFilter enforcement, provider/model routing, depth handling, background jobs, cancellation and generic timeout policy.

### Recall

Do not add new direct `~/.dsh/sessions` storage assumptions.

`mop_recall` now uses DSH provider-independent `sessionQuery.filterSessions/filterEvents` by default, so normal recall reads the logical live-preferred session corpus without enabling the optional FTS index. The 0.1.x zstd scanner remains only for `caseSensitive=true`, a missing native seam, or a non-cancellation native failure.

### Learn

Keep the workflow concept "completed work -> reusable skill candidate", but stop owning skill catalog/discovery infrastructure. Target DSH's native skill registry/filesystem format.

### Diagnostics

Treat DSH token projections and other native telemetry as source data. MiOpIIk diagnostics may normalize/report them but should not duplicate the accounting engine.

## Delivery sequence

### Phase A — 0.1.x maintenance freeze — complete

- lifecycle and compatibility boundaries documented;
- 0.1.x feature growth frozen;
- no package unpublished;
- no separate 0.1.14 release was required before starting the 0.2 implementation train.

### Phase B — 0.2 compatibility adapters

- recovery absorbs event-driven checkpoint behavior (**implemented first**: default runtime routes `auto-turn` / `auto-error` through `dsh-miopiik-tool-recovery`; standalone `dsh-miopiik-checkpoint` remains compatibility-only for the migration window);
- diagnostics absorbs capability/run-stats behavior (**implemented second**: `dsh-miopiik-diagnostics` owns both implementations; the old packages delegate as compatibility wrappers and are removed from the default meta/preset rows);
- magic-keywords and learn leave the default suite (**implemented third**: packages, standalone bundle patches and tests remain; default meta/preset no longer mounts them).
- executor becomes a thin native-subagent policy adapter (**implemented next**: `mop_spawn_executor` keeps the explicit zero-default route/leaf/persona/tool-scope contract over native `ctx.subagents.start`; every published `SubagentRun` now follows the upstream mandatory disposal contract on success, failure, cancellation and timeout);
- recall becomes a native session-query adapter or compatibility shim (**implemented next**: `mop_recall` keeps its public contract but defaults to provider-independent `sessionQuery.filterSessions/filterEvents`; case-sensitive, missing-seam and failed-native paths retain the 0.1.x zstd fallback);
- learn targets native skills;
- magic-keywords becomes opt-in.

Existing npm package names remain resolvable.

### Phase C — default-bundle reduction — complete for 0.2.0

- default meta/preset runtime is reduced from nine historical rows to five: recovery, executor policy adapter, model-auth, diagnostics and recall;
- checkpoint/capabilities/run-stats remain compatibility packages;
- magic-keywords/learn remain explicit opt-ins;
- legacy packages remain individually installable and are not npm-deprecated in 0.2.0;
- real DSH Composition has passed against both the pinned compatibility commit and upstream `master` for the converged stack.

## Acceptance gates

The 0.2.0 release candidate reruns these acceptance gates before publish:

1. old 0.1.x installs have a documented upgrade path;
2. checkpoint/rewind behavior has no recovery regression;
3. route authorization still fails closed;
4. executor behavior is covered by real DSH composition tests rather than mock-only tests;
5. recall replacement passes workspace and current-session search cases;
6. token/run reporting reconciles with DSH's native token projection;
7. the preset has no hidden dependency on a package removed from the default bundle.

## Non-goals

- Do not turn MiOpIIk into a second generic Harness runtime.
- Do not duplicate a stable DSH subsystem only to preserve historical implementation code.
- Do not optimize for npm package count alone; compatibility and clear ownership matter more.
- Do not unpublish packages to make the repository look cleaner.
